## Design notes and deviations (read these)
- Change A fires on every PATCH whose resulting agent.status is "paused", per spec, so a PATCH of any other field on an already-paused agent also sweeps queued/running runs (errorCode agent_paused). That matches pause semantics but is a behavior addition on paused agents; flagging it.
- Change B placement: issue path guard sits immediately before the getHeartbeatDailyCapBlock check, not literally immediately before the agentWakeupRequests insert, because admitExplicitNativeContinuation (explicit-native-continuation.ts:71, writes at lines 280-294: nativeRunFinalizations, heartbeatRuns, issueRecoveryActions) runs between them and would commit side effects for a wake we then skip. Non-issue path guard sits right after the existing agents FOR UPDATE, ahead of the daily-cap skip, so a paused agent records agent.not_invokable rather than a daily-cap reason.
- Outcome kind: both txs return { kind: "skipped" }. Consumers: issue path heartbeat.ts treats "deferred"|"skipped" identically (return null); non-issue path `if (queueOutcome.kind === "skipped") return null`. No heartbeat_runs row, no startNextQueuedRunForAgent, no live event.
- Skipped row shape mirrors writeSkippedRequest (durableReceiptFields, source, triggerDetail, reason "agent.not_invokable", payload, status skipped, actor fields, idempotencyKey, error "Agent is not invokable in its current state", finishedAt). Exceptions: when executionWaitRequestId is set no row is inserted (the saved deferred request stays deferred; the next admission is rejected by the pre-check), and when the agent row is gone nothing is inserted.
- In the race window a user-actor wake now returns null instead of the 409 the pre-check would throw. Narrow window; flagging.
- Issue-path re-read is a plain select with no agent lock, as specified, so a pause committing after that read but before the tx commits can still leave one queued row; change A's repeat-pause sweep and POST pause's cancelActiveForAgent cover that residue. Not closed by B alone.

## Follow-up 2: claim-time gate

Decision recorded (coordinator): enabled:false = allow for wakes stays as built (gate off means no effect; production runs enabled:true).

### Choke point
- Every path that executes a queued run goes through `claimQueuedRun`. executeRun calls it for any run still queued (heartbeat.ts executeRun, `if (run.status === "queued") claimQueuedRun(run)`), and startNextQueuedRunForAgent calls it for each run it claims.
- The other executeRun callers are native restart and session-resume dispatch (heartbeat.ts ~15063, ~18998, ~20076). They pass already-claimed native leases, and executeRun still routes any queued run through claimQueuedRun.
- startNextQueuedRunForAgent has an earlier exit: it returns without claiming when the agent is not invokable or has no free slot, so rows for a paused agent sat queued. That is the race-row case.

### Change
- New helper `cancelQueuedRunAtClaim(run, errorCode, reason)` does what cancelQueuedRunForBlockedDependencies does:
  - setRunStatus cancelled with finishedAt now, the error message and errorCode;
  - setWakeupStatus skipped;
  - clears the issue execution lock where executionRunId is this run;
  - appends a run event.
- startNextQueuedRunForAgent: after loading the agent and before the invokability and slot checks, it cancels every queued run (respecting the worktree cutoff) when the gate excludes the agent (fleet_release_gate_not_allowed) or the agent is paused (agent_paused), then returns.
- claimQueuedRun: after its invokability check, the gate is checked again and a refused run is cancelled with fleet_release_gate_not_allowed. The existing invokability cancel now passes errorCode agent_paused when the reason is paused; it was "cancelled" before.
- Terminated agents: unchanged. They were already cancelled through shouldCancelRunsForNonInvokableAgent and cancelActiveForAgentInternal, with errorCode "cancelled".
