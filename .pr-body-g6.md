## Thinking Path

> - Paperclip manages AI agents and their work.
> - The heartbeat scheduler admits assigned work and controls agent concurrency.
> - A certification cycle must run exactly three selected issues at the same time.
> - Normal work must remain deferred during that bounded cycle.
> - A process failure must not leave an agent at a temporary concurrency setting.
> - This pull request adds a durable, board-owned certification reservation.
> - The benefit is exact admission, safe recovery, and auditable restoration.

## Linked Issues or Issue Description

**What existing behavior does this improve?**

This change improves heartbeat admission and runtime concurrency control for bounded certification runs.

**Subsystem affected**

Cross-cutting: server REST routes, orchestration services, database schema, shared validation, and scheduler admission.

**Current behavior**

The board cannot reserve exactly three issues for one agent. A temporary concurrency change can admit unrelated work. A lost release response can also leave the caller unable to prove the committed result.

**Proposed behavior**

The board creates a reservation for exactly three distinct assigned issues. Paperclip admits one run for each member and defers other work. Verified release restores the prior runtime configuration. Historical lookup and same-mode replay recover a lost release response.

**Reason and benefit**

This control lets operators run exact concurrency certification without stopping normal fleet work. Durable containment prevents duplicate or unrelated runs from contaminating the result.

**Breaking changes**

None. The new routes and tables are additive. Normal admission remains unchanged when no reservation is active.

## What Changed

- Add durable certification reservation and member tables.
- Add board-only create, active read, historical read, verify-and-release, and abort routes.
- Restrict reservations to exactly three distinct actionable issues.
- Bind one admitted run to each reserved issue.
- Defer non-member wakes and claims while a reservation is active.
- Restore the prior runtime configuration on release, abort, or expiry.
- Make verified release replay safe after a committed response loss.
- Add retryable containment for abort and expiry.
- Add service, route, migration, and authorization tests.

## Risks

- The migration adds two tables and related indexes.
- Active reservations change admission only for the selected agent.
- Abort and expiry pause the agent until an operator confirms recovery.
- The deployment must install this change before the reservation-aware autoscaler.
